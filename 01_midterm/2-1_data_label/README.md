# 2-1. 데이터 수집·정제 및 위험 라벨 정의

## 목적

Amazon Reviews 2023의 Appliances 카테고리 리뷰 원본을 상품(`parent_asin`) × 달력월(`year_month`) 단위의 분석 데이터로 변환한다.

원본 데이터의 한 행은 “특정 사용자가 특정 상품에 작성한 리뷰 1개”다. 하지만 이 프로젝트에서 예측하려는 것은 개별 리뷰의 별점이 아니라, 특정 상품이 특정 달에 어떤 상태였으며 다음 달에 품질 악화 신호가 나타날 것인가다.

따라서 같은 상품에 같은 달 작성된 리뷰를 하나로 묶어, 해당 월의 리뷰 수, 평균 별점, 저평점 비율, 검증 구매 비율 등을 계산한다.

예를 들어 원본 리뷰가 아래와 같다고 하자.

```text
상품 A / 2021-05 / 5점 / "잘 작동함"
상품 A / 2021-05 / 1점 / "한 달 만에 고장남"
상품 A / 2021-05 / 4점 / "대체로 만족"
```

이를 아래처럼 상품×월 행 하나로 변환한다.

```text
상품 A / 2021-05
- 해당 월 리뷰 수: 3개
- 해당 월 평균 별점: 3.33점
- 해당 월 저평점(1~2점) 리뷰 수: 1개
- 해당 월 저평점 비율: 33.3%
```

이렇게 만들어진 t월의 정보만 사용해, 다음 달인 t+1월에 저평점 리뷰가 급증할 위험을 예측하는 것이 목표다.

핵심 질문은 다음과 같다.

> 별점·리뷰 수 등 정형 정보만 사용한 모델보다, 리뷰 텍스트에서 나타나는 부정 표현 및 결함 언급의 변화까지 함께 사용한 모델이 미래 상품 품질 악화를 더 정확히 예측할 수 있는가?

2-1에서는 상품×월 데이터와 위험 라벨을 만든다. 리뷰 텍스트의 구체적인 의미를 분석해 NLP 피처를 만드는 작업은 2-3에서 수행한다.

## 분석 기간과 단위

- 분석 단위: `parent_asin × year_month`
  - `parent_asin`은 색상·용량·규격 같은 세부 옵션을 하나로 묶는 대표 상품 ID다.
  - `year_month`는 30일씩 임의로 나눈 구간이 아니라 UTC 기준 달력월(`YYYY-MM`)이다.

- 입력 시점(t월): `2016-01 ~ 2023-02`
  - 한 행은 “해당 상품의 t월 말 상태”를 뜻한다.
  - 모델 입력 피처에는 t월 말까지 확인 가능한 정보만 들어간다.

- 예측 결과(t+1월): `2016-02 ~ 2023-03`
  - t월 행의 정답은 바로 다음 달인 t+1월의 리뷰 결과로 생성한다.
  - 예를 들어 `2021-05` 행은 2021년 5월까지의 정보로 2021년 6월의 저평점 급증 여부를 예측한다.

- 2023-04 이후 제외
  - 원본 데이터는 2023년 9월까지 존재하지만 2023년 4월부터 월별 리뷰 수가 급격히 감소한다.
  - 실제 상품 활동 감소라기보다 데이터 수집 종료에 따른 불완전한 후반 구간일 가능성이 높다.
  - 이 기간을 포함하면 다음 달 리뷰 수가 인위적으로 적어지고 저평점 비율 라벨이 불안정해질 수 있으므로 분석에서 제외한다.

- 직전 3개월 기준선 계산용 기간: `2015-11 ~`
  - 2016년 1월의 위험을 판단하려면 2015년 11월, 12월, 2016년 1월의 저평점 비율이 필요하다.
  - 따라서 최종 학습 행은 2016년 1월부터 시작하지만 과거 기준선 계산을 위한 정제 리뷰는 2015년 11월부터 보관한다.

## 최종 위험 라벨

예측 대상은 `is_low_rating_surge` 하나다.

```text
is_low_rating_surge = 1
```

은 아래 네 조건을 모두 만족할 때 부여한다.

1. t+1월 전체 리뷰 수가 5개 이상

   리뷰가 1개뿐인데 그 리뷰가 1점이면 저평점 비율은 100%가 된다. 이런 작은 표본으로는 실제 품질 악화인지 판단하기 어려우므로, 다음 달 리뷰가 최소 5개 이상인 경우만 라벨을 만든다.

2. t월을 포함한 직전 3개월 전체 리뷰 수가 5개 이상

   다음 달의 상태가 기존보다 악화되었는지 비교하려면 과거 기준선도 최소한의 리뷰 수를 가져야 한다. 직전 3개월은 `t-2월`, `t-1월`, `t월`을 뜻한다.

3. t+1월의 1~2점 리뷰 비율이 30% 이상

   저평점 리뷰는 별점 1점 또는 2점으로 정의한다.

```text
next_low_rating_ratio
= t+1월의 1~2점 리뷰 수 / t+1월 전체 리뷰 수
```

4. t+1월 저평점 비율이 직전 3개월 저평점 비율보다 15%p 이상 높음

   단순히 다음 달 저평점 비율이 높은 상품만 잡으면 원래부터 평판이 낮았던 상품도 위험으로 분류된다. 프로젝트 목표는 이미 나쁜 상품을 찾는 것이 아니라, 기존 상태보다 새롭게 품질이 악화된 상품을 조기에 감지하는 것이다.

```text
next_vs_past_3m_low_rating_change
= t+1월 저평점 비율 - 직전 3개월 저평점 비율
```

여기서 15%p는 15% 증가가 아니라 15퍼센트포인트 증가다.

```text
직전 3개월 10% → 다음 달 25%: +15%p, 위험 조건 충족
직전 3개월 20% → 다음 달 30%: +10%p, 위험 조건 미충족
```

라벨 후보를 비교한 결과는 다음과 같다.

| 조건 | 위험 행 비율 |
| --- | ---: |
| 다음 달 저평점 비율 30% 이상 | 16.5% |
| 30% 이상 + 직전 3개월 대비 10%p 상승 | 10.73% |
| 30% 이상 + 직전 3개월 대비 15%p 상승 | 9.00% |
| 30% 이상 + 직전 3개월 대비 20%p 상승 | 6.87% |

너무 넓은 10%p 기준과 너무 엄격한 20%p 기준 사이에서, 위험 사례 수와 “급증”이라는 의미를 함께 고려해 15%p 기준을 선택했다.

최종 학습 데이터는 68,087개 상품×월 행이며, 위험 라벨은 6,448개(9.47%)다.

## 모델 사용 시 주의

`product_month_labeled.parquet`에는 라벨을 검증하거나 결과를 해석하기 위한 t+1월 정보도 함께 보관되어 있다.

다음 컬럼들은 미래 정보이므로 모델 입력 피처로 사용하면 안 된다.

```text
next_review_count
next_avg_rating
next_low_rating_count
next_low_rating_ratio
next_vs_past_3m_low_rating_change
```

이 값들은 t월 시점에서는 아직 알 수 없는 t+1월의 실제 결과다. 이를 모델에 넣으면 미래를 미리 본 상태로 학습하게 되어, 검증 성능이 비정상적으로 높게 나오는 데이터 누수 문제가 발생한다.

모델 학습 시에는 다음처럼 구분한다.

```text
예측 대상(y)
- is_low_rating_surge

입력 피처(X)로 사용 가능
- review_count
- avg_rating
- low_rating_count
- low_rating_ratio
- verified_purchase_ratio
- mean_helpful_vote
- text_available_ratio
- past_3m_review_count
- past_3m_low_rating_count
- past_3m_low_rating_ratio
- 2-3에서 새로 생성할 NLP 피처

모델 입력에서 제외
- parent_asin: 상품 식별용 키
- year_month: 시간순 학습·검증 분할용 키
- next_로 시작하는 모든 열
- next_vs_past_3m_low_rating_change
- is_low_rating_surge: 예측 대상 자체
```

2-2 담당자는 이 파일로 정형 피처 베이스라인 모델을 만들고, 2-3 담당자는 `reviews_clean.parquet`의 리뷰 텍스트를 `parent_asin × year_month` 기준으로 집계해 NLP 피처를 만든 뒤 같은 키로 최종 학습 데이터에 결합한다.

원본·중간·최종 Parquet 데이터는 대용량이므로 GitHub에 올리지 않는다. GitHub에는 재생성 코드, 이 문서, 데이터 사전, 요약 CSV만 올린다.
